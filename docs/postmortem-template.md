# Postmortem 模板

Blameless，只写事实，不写“谁的错”。

## 概要

- 日期：
- 严重度：sev1 / sev2
- 持续时间：
- 影响：丢了几单 / 错发了几张卡 / 影响了几个买家

## 时间线

按时间顺序写，每条带时间戳和来源（audit_log / Stripe 后台 / 买家反馈）：

- 02:13：第一笔异常订单出现
- 02:15：kill switch 自动跳闸
- ……

## Root cause

只写根因，不写表象。比如“`src/fulfill.js` 的锁卡查询没加状态守卫，两个并发抢到同一张卡”，
不要写“系统出 bug 了”。

## 是怎么发现的

告警、用户反馈、还是对账发现的？发现花了多久？

## Action items

每条都要有负责人（bot 或人）和截止时间：

| Action | 负责人 | 截止 |
| --- | --- | --- |
| 给锁卡查询加状态守卫 + 测试 | bot | |
| 对账加上孤儿卡检查 | bot | |
| 把这类报错的熔断阈值从 5 次调到 3 次 | 人 | |

## 经验

下次同类问题直接按 action items 走，不再从头排查。
